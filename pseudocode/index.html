1. See what the algorithm is doing


Compile checks the syntax, declared names and calls, then translates the program into source-mapped bytecode. It does not execute the source. Type, initialisation, array-bound and file-mode checks also run during execution. Bytecode shows the actual instructions executed by this page’s virtual machine.


Step (F10) executes the next source step. The green line is the next step, not the one just completed. Changed values are highlighted in amber. Structural-only endings such as ENDIF, comments and blank lines are skipped. Loop conditions and NEXT are executable steps.


Run (Ctrl/Cmd + Enter) continues until the end, an INPUT, an error or a breakpoint. Choose a slower speed for a live demonstration. A breakpoint stops before the marked line. Pause (Esc) stops between steps. Use Step over (Shift + F10) to execute a call without visiting its body; breakpoints inside it still apply.


Back (Alt + Left) restores the previous execution state, including variables, arrays, the call stack, output, virtual files and the random seed. Up to 80 recent steps are retained, within a memory budget. Reset clears execution and restores starting files, but keeps source and breakpoints.


Watch accepts expressions such as Total / Number or Values[Index]. It cannot call user functions or random functions. Stack displays active calls and local scopes. Expand Execution trace to see variable snapshots and export a CSV trace table.


A function call can suspend its caller mid-expression. The debugger steps into the function, then highlights the caller again to finish that expression. An inline CASE label may likewise have a test step and a statement step. Use Step over for a single caller-level action.


2. Declarations, assignment and input/output


DECLARE Score : INTEGER
DECLARE Name : STRING
DECLARE Price : REAL
DECLARE Ready : BOOLEAN
DECLARE Grade : CHAR
CONSTANT PassMark = 50

Score ← 75
Name ← "Mai"
Grade ← 'A'
Ready ← TRUE
OUTPUT Name, " scored ", Score
INPUT Score


Declare variables before executing code that uses them. CHARACTER is accepted as an alias for CHAR. A declaration creates an uninitialised value, not an automatic zero. DECLARE A, B : INTEGER is supported. Constants must contain a literal, not an expression. Identifiers and keywords are case-insensitive; text values are case-sensitive.


Use ←, <-, <-- or := for assignment. Use = for comparison. Single quotes hold exactly one character; double quotes hold a string. Comments start with //. Tab indents four spaces. Enter preserves indentation; the format button re-indents structured blocks.


Each OUTPUT adds a line. Comma-separated values are joined without extra spaces; include spaces inside text. INPUT pauses in the console. Type values without quotes. Boolean input must be TRUE or FALSE. Invalid input can be corrected without resetting.


PurposeOperators
Arithmetic+ - * / DIV MOD ^
Compare= <> < > <= >=

Concatenate text"Hello " & Name


/ always returns REAL, even for 4 / 2. INTEGER values may be assigned to REAL variables, but the reverse needs INT(). DIV truncates towards zero; MOD uses the corresponding remainder. & requires text operands, not numbers; use NUM_TO_STR() or separate OUTPUT values. AND and OR short-circuit. Use parentheses to make Boolean intent clear.


3. Decisions and loops


IF Score >= 50 THEN
    OUTPUT "Pass"
ELSE
    OUTPUT "Keep practising"
ENDIF

FOR Number ← 1 TO 5
    OUTPUT Number
NEXT Number

WHILE Number > 0
    Number ← Number - 1
ENDWHILE

REPEAT
    INPUT Score
UNTIL Score >= 0 AND Score <= 100


THEN may be on its own line. ELSEIF … THEN and ELSE IF … THEN chains are accepted. An optional DO is allowed after a WHILE condition. FOR bounds are inclusive and evaluated once on entry; STEP defaults to 1 and may be negative but not zero. The counter must be INTEGER. NEXT increments the counter before its limit test, leaving it one increment beyond the range on normal exit.


CASE OF Score
    80 TO 100 : OUTPUT "Distinction"
    50 TO 79 : OUTPUT "Pass"
    OTHERWISE : OUTPUT "Try again"
ENDCASE


CASE executes the first matching branch, with no fall-through. Labels can be values, comma-separated values, or ranges. A branch may contain several statements on following lines. OTHERWISE is optional and must be last.


4. Arrays with explicit bounds


DECLARE Marks : ARRAY[1:5] OF INTEGER
DECLARE Board : ARRAY[0:2, 0:2] OF CHAR
Marks[1] ← 85
Board[0,2] ← 'X'
OUTPUT Marks[1]


One- and two-dimensional arrays are supported. Indices must be INTEGER and within the declared bounds, which may use previously initialised constants or variables. Expand an array in the Variables tab to inspect cells. Use loops to initialise or output its elements. Whole-array assignment copies an array with matching bounds and element type.


5. Procedures, functions and scope


FUNCTION Double(Number : INTEGER) RETURNS INTEGER
    RETURN Number * 2
ENDFUNCTION

PROCEDURE Increase(BYREF Value : INTEGER)
    Value ← Value + 1
ENDPROCEDURE

DECLARE Answer : INTEGER
Answer ← Double(5)
CALL Increase(Answer)
OUTPUT Answer


Definitions are top-level and can appear before or after their calls. Parameters default to BYVAL (copy). BYREF is available for procedures and refers to a writable caller variable or array element. Once specified, BYVAL or BYREF continues to following parameters until changed. Array parameters require explicit, matching bounds; scalar parameters can be used in those bounds. Functions return scalar values and may recurse.


Main-scope variables are global. Subprogram parameters and declarations are local to that call. A local identifier hides a global one with the same name. Variables belong to the main/subprogram scope, not individual IF or loop blocks. RETURN exits immediately. Every executed path through a function must return a value.

7. Virtual text files


DECLARE LineText : STRING
OPENFILE "names.txt" FOR READ
WHILE NOT EOF("names.txt")
    READFILE "names.txt", LineText
    OUTPUT LineText
ENDWHILE
CLOSEFILE "names.txt"


Create or import starting files in the Files tab. READFILE reads one line into a STRING. OPENFILE "results.txt" FOR WRITE creates or truncates a file; APPEND preserves existing text. WRITEFILE "results.txt", "Some text" writes a line. Use NUM_TO_STR for numeric data. CLOSEFILE closes the handle. Export files to keep generated data outside this page.


8. What this version does and does not support


This is an independent Cambridge-style teaching dialect, not an official Cambridge product or a universal natural-language pseudocode parser. The supported syntax above is the contract. It follows common Cambridge control-flow, declaration, array and subprogram conventions; convenience aliases and built-ins are explicitly documented here. It does not claim complete IGCSE, A Level or IB language conformance.


Not supported: records and user-defined types, DATE values, classes/objects, pointers, sets, random-access/binary files, networking, free-form English instructions, or arbitrary programming-language code. Put each statement on one source line, except the supported CASE label form. STOP is a convenience extension that ends the program.


Safety limits: 120,000 source characters; two array dimensions; 10,000 elements per array and 20,000 live cells; call depth 100; one million bytecode operations or 100,000 source steps. Exact INTEGER range is ±9,007,199,254,740,991; REAL uses browser floating-point arithmetic. These are teaching/runtime choices, not examination requirements.


Back retains at most 80 steps within an estimated 12 MB snapshot budget. The trace retains the latest 2,000 records and up to 60 visible variable names per snapshot; the on-page mini trace shows the latest 150. Arrays appear as compact values in traces and full cells in the inspector (up to 400 displayed). The console retains at most 1,000 lines or 250,000 characters. Older records are removed to keep the page responsive.


Your source and starting files are autosaved in this browser where local storage is available. Source and data are never sent to a server by this page. Execution is local, uses a custom virtual machine, and never evaluates source as JavaScript. Save a source file for a reliable backup. Editing source resets the current execution; the editor is locked during Run.
